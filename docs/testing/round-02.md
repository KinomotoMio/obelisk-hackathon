# 第 2 轮测试说明（2026-10-07）

> 对应 `hackathon` 分支上带有本文件的那次提交。安装方法见 [测试轮次](README.md#安装每一轮通用)。所有链上操作都在 BOT Chain **测试网**上进行，区块浏览器是 <https://scan.bohr.life>。
>
> 第 1 轮的反馈还没有汇总。如果你已经测过第 1 轮，那些问题照常反馈即可。这一轮只测新增的部分，第 1 轮的场景不用重跑。

## 一、愿景（一分钟版）

和第 1 轮一样：Obelisk 是你和 AI 编程助手之间的记忆层，这次比赛做它的"出口"。真实的 AI 工作过程可以安全地离开你的电脑，并且被证明、被复用。具体是三件事：私密分享、Skill 资产化、真实使用证据。完整说明见 [第 1 轮 · 愿景](round-01.md#一愿景一分钟版) 和 [愿景 README](../vision/README.md)。

这一轮补上的是第三件事的后半段，以及它的去处：

- **用得顺不顺**：每次调用之后，由你本机的 AI 编程助手判断这次调用属于什么场景、结果是顺利、返工还是失败，再上报到链上。每个场景单独算顺利率。
- **衍生**：在别人铸造的 Skill 上改出自己的版本。铸造时记下父 Skill，族谱多出一个分支，原作者的贡献有据可查。
- **AI 能力履历**：用你自己的真实历史和链上记录生成一页履历，上面的每个数字都能核对。
- **给外面的人看**：Skill 市场和项目预览是公开网页，评委和投资人用浏览器打开就能看，不用装 App。

## 三、愿景和现状的差距

原因的分类和第 1 轮相同：**排期**、**按设计延后**、**外部依赖**、**不好实现**、**已知缺陷**。

| 差距 | 原因 | 说明 |
| --- | --- | --- |
| 主网部署 | 外部依赖 | 等拿到主网 BOT。代码和测试网完全一样，部署一次合约、改一下配置即可。 |
| 演示用的调用量和场景数据 | 排期 | Playground 流程已经能跑；正式跑之前，要先确定演示需要什么效果。在那之前，详情页、市场页和履历上的数字都只来自真实操作（包括你测试时的操作）。 |
| 项目预览页是示意内容 | 排期 | 页面已经做好；Playground 正式跑完后只需换数据，标注会从"示意内容"变成"真实运行"，每笔交易都能点到区块浏览器。 |
| App 设置页的钱包区 | 排期 | 还是用命令行管理钱包。 |
| App 里按名字搜索 Skill | 排期 | App 里仍然按编号打开；网页 `/market` 已经有完整列表。 |
| 上架、付费、分成、收入 | 按设计延后 | 阶段 2 才真正实现；`/market/stage-2` 是标明"阶段 2 预览"的展示页，数字都标"示例"。 |
| 判断要用你自己的 AI 额度 | 按设计 | 判断在你本机运行，用的是你的 Codex 或 Claude Code 登录，内容不会离开你的电脑。每次判断前都会先预览要读多少内容、分几次运行。 |
| 场景少于 5 次可判断的调用时不显示顺利率 | 按设计 | 样本太少的百分比没有意义，页面会显示"样本不足"和已经判断的次数。 |
| 履历的能力维度没有顺利率 | 不好实现 | 判断只覆盖已铸造 Skill 的调用，整段历史没有逐个 session 的判断。履历页上写明了这一点，Skill 表里的顺利率是真实的。 |
| 上报数据防篡改 | 不好实现 | 同第 1 轮，见 [质疑与回应 C1](../vision/10-challenges.md)。 |
| 趋势图按上报时间统计 | 不好实现 | 同第 1 轮。 |
| 用户新建的场景标签只记在本机 | 排期（P2） | 跨用户汇总、收进下一版词表，放到赛后。 |
| Codex 里的 Skill 调用识别不完整 | 已知缺陷（P2） | Codex 会漏记或重复记，所以这一轮"调用并上报"请在 Claude Code 里做。 |
| 打开 session 的瞬间可能漏掉一条实时更新 | 已知缺陷（P2） | 同第 1 轮。 |

## 四、这一轮要测的场景

先跑场景 0。场景 1 到 3 依次依赖，场景 4、5 可以随时测。除了功能对不对，也请留意体验：文案是否看得懂、下一步是否清楚、等待是否太久、页面是否像一个完成的产品。

### 场景 0：更新

1. 在仓库目录里拉取最新代码，重新运行脚本：
   ```bash
   git pull
   sh scripts/hackathon-env.sh
   ```
   第 1 轮建好的两个角色、钱包和索引都会保留，不用重新建。
2. 打开 App。**应该看到**：
   - 左上角是新的方尖碑标志和"Obelisk"字标；
   - Dock 里是 Obelisk 图标，不是 Electron 默认图标，大小和旁边的应用一致。

### 场景 1：铸造「AI 能力履历」Skill（角色 A）

这个 Skill 是我们写好、准备拿去铸造的，所以由角色 A 当作者来铸造，而不是从 A 的历史里沉淀。

1. 在角色 A 的终端里，把它存进 A 的 Skill 库：
   ```bash
   obelisk skill save minted-skills/ai-capability-resume/draft.json
   ```
   这条命令要在仓库目录里运行。
2. 在 A 的 App 里进入 **Skill**，它会出现在"待确认的草稿"里。点"确认并铸造"，把复制的 prompt 粘贴到 Claude Code。
3. **应该看到**：先给出铸造预览，你确认后才上链；交易能在 scan.bohr.life 查到。
4. 记下 Skill 编号。

### 场景 2：取用、生成履历、判断结果（角色 B）

1. 在角色 B 的 App 里进入 **Skill**，在"Skill 编号"里输入场景 1 的编号，打开详情页，点"取用"。
2. 在 `~/.obelisk-hackathon/workspace` 里打开 Claude Code，粘贴复制的 prompt，并在末尾加一句"装到当前项目"。**应该看到**：先展示完整正文，说明它和链上指纹一致；你确认后才安装。
3. 新开一个 Claude Code session，输入 `/ai-capability-resume 用我最近 30 天的历史生成 AI 能力履历`。
4. **应该看到**：
   - 先用两三行告诉你它看到了什么，例如多少个 session、多少个活跃日；
   - 最后生成一个 `ai-capability-resume.html` 文件。
5. 用浏览器打开这个文件。**应该看到**：
   - 页头有 Obelisk 标志；顶部数字、能力维度雷达图、两到四个代表性问题，每个问题都附一条"佐证可私密出示"的 prompt；
   - 底部 Skill 表里的「铸造记录 ↗」能打开测试网上的交易；
   - 能力维度下方说明了归类方式，以及为什么维度没有顺利率；
   - 手机宽度下排版正常；用浏览器打印预览时，页面变成适合白纸打印的浅色版。
6. 换几个说法，再用这个 Skill 生成几次（每次都新开 session），加上第一次，一共至少 5 次。场景要有变化，例如"给前端岗位""给数据分析岗位"。
7. 对 Claude Code 说"判断 Skill 调用的结果"。**应该看到**：
   - 先预览：要判断几次调用、分几次运行、每次读多少内容，并说明用的是你本机的 Codex 还是 Claude Code；
   - 你确认后才运行；最后列出每次调用的场景和结果（顺利 / 返工 / 失败 / 无法判断）；
   - 再说一次，它会说没有新的可判断调用，不会重复判断。

   刚用完的调用要安静 30 分钟才会被判断。如果它说没有可判断的调用，过一会儿再试。
8. 说"上报 Skill 使用情况"。如果你在第 1 轮还没开启上报，它会先预览再开启。**应该看到**：上报的预览里包含场景和结果；如果要发多笔交易，会写明笔数。确认后，交易可查。

### 场景 3：看实测场景，然后衍生（A 看，B 改）

1. 回到角色 A 的 App，打开履历 Skill 的详情页。**应该看到**：
   - 真实调用数等于 B 的使用次数，钱包数为 1；
   - "实测场景"列出判断出的场景，每个场景有自己的顺利率；不到 5 次可判断调用的场景显示"样本不足"，没有被判断过的场景显示"未判断"；
   - 鼠标悬停在某个场景上，能看到顺利、返工、失败、无法判断各几次。
2. 在角色 B 的 App 里打开同一个详情页，点"在此基础上修改"，把 prompt 粘贴到 Claude Code，在"我想改成："后面写一个方向，例如"设计师作品集"。
3. **应该看到**：
   - 它先读父 Skill，再说明草稿里哪些部分来自父 Skill、哪些是这次改的；
   - 草稿出现在 B 的 Skill tab 里；铸造预览里写着父 Skill 的编号。
4. 铸造后，在 A 和 B 的 App 里分别打开父 Skill 和新 Skill 的详情页。**应该看到**：两边的族谱里都有这条新分支。

### 场景 4：公开网页（浏览器，不用 App）

用电脑和手机分别打开 <https://obelisk-service.kinomotomiovo.workers.dev/market>。

1. **Skill 市场**。**应该看到**：
   - 测试网上已铸造的 Skill，最新的在前，包括你在场景 1 和场景 3 里铸造的两个；
   - 点进去，数字和 App 详情页里的一致：调用量、钱包数、实测场景、族谱。
2. 点"阶段 2 预览"。**应该看到**：上架、分成、收入、按上下文付费，所有数字都标着"示例"；分成按所选 Skill 的真实族谱计算。
3. 从顶栏进入 **项目预览**。**应该看到**：
   - 页面三处标明"示意内容"；
   - 左边 9 个剧本步骤，中间是各角色看到的画面和链上时间线，右边可以切换角色；
   - 选中一个角色后，只显示他的画面；如果他不在当前这一步，会提示他出现在第几步；
   - 键盘左右键可以翻页，复制地址栏的链接重新打开，会回到同一步；
   - 手机上翻页按钮固定在底部，不会挡住页面最后的文字。
4. 打开一个第 1 轮生成的分享链接，或者重新分享一次。**应该看到**：阅读页顶部是新 logo；网络名显示为"BOT Chain 测试网"；出错时的提示是看得懂的中文。

### 场景 5：用 Codex 接 App 的 prompt

1. 在 App 的 **设置** 里，把"复制给"切换到 Codex。**应该看到**：下面的示例 prompt 从斜杠命令变成一句点名 skill 的话。
2. 在 Skill tab 里点任意一个复制按钮（比如草稿的"继续修改"），然后在 `~/.obelisk-hackathon/workspace` 里打开 `codex` 并粘贴。**应该看到**：Codex 认出要用哪个 Obelisk skill，并按同样的流程执行，比如先预览再确认。
3. 测完把设置切回 Claude Code。
