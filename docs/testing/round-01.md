# 第 1 轮测试说明（2026-10-07）

> 对应 `hackathon` 分支上带有本文件的那次提交。安装方法见 [测试轮次](README.md#安装每一轮通用)。所有链上操作都在 BOT Chain **测试网**上进行，区块浏览器是 <https://scan.bohr.life>。

## 一、愿景（一分钟版）

Obelisk 原本是你和 AI 编程助手之间的记忆层：它保存你和 Claude Code、Codex 等工具的完整对话，AI 需要时可以回头查自己当初怎么做的、为什么这样做。完整说明见 [愿景 README](../vision/README.md) 和 [Why Obelisk](../vision/why-obelisk.md)。

这次比赛做的是它的"出口"：让这些真实的 AI 工作过程可以安全地离开你的电脑，并且被证明、被复用。具体是三件事：

1. **私密分享**：把一段对话只给指定的人看。打开次数、有效期、撤回都由链上规则决定，接收者打开后会留下链上回执。
2. **Skill 资产化**：用一句话从你自己的历史里沉淀出 Skill，并附上出处；铸造上链后归属清楚，别人可以取用，也可以在它的基础上衍生。
3. **真实使用证据**：统计 Skill 被真实调用了多少次、来自多少个钱包、在什么场景下用、用得顺不顺，而不是只看安装量。

产品形态是"命令行优先，App 负责展示"：所有操作都由你在 Claude Code 里说一句话完成，App 上的按钮只是复制一段 prompt 给你粘贴。

## 三、愿景和现状的差距

每一项都注明了差距的原因：

- **排期**：在计划内，比赛期间是否来得及做，要看时间；
- **按设计延后**：愿景里本来就安排在阶段 2 或阶段 3；
- **外部依赖**：需要别人配合；
- **不好实现**：有技术或成本上的难点，还在讨论；
- **已知缺陷**：做的时候发现的问题，已记录。

| 差距 | 原因 | 说明 |
| --- | --- | --- |
| 主网部署 | 外部依赖 | 比赛要求部署到主网。代码和测试网完全一样，拿到主网 BOT 后部署一次合约、改一下配置即可。 |
| 实测场景与顺利率的真实数据 | 排期（P1） | 需要在每次调用后，由本机的 AI 编程助手判断场景和结果。上报格式已经预留了位置。 |
| 演示数据（Playground） | 排期（P1） | 在一台电脑上让多个模拟用户真实地跑一遍流程，产生演示用的调用量和场景分布。现在详情页上能看到的数字，只来自你自己的真实操作。 |
| 在已有 Skill 上衍生 | 排期（P1） | 族谱展示和"铸造时声明父 Skill"都已经能用；"用「沉淀 Skill」在已有 Skill 基础上改出新版本"这一步还没做。 |
| AI 能力履历 | 排期（P1） | 依赖前面的真实数据。 |
| App 设置页的钱包区 | 排期（P1） | 目前用命令行管理钱包。 |
| 市场、付费、分成、收入页面 | 按设计延后 | 阶段 1 只做截图展示（P2），阶段 2 才真正实现。 |
| 在 App 里直接发起沉淀、接收分享、按场景搜索 | 按设计延后 | 阶段 2。 |
| 泄露追踪（看不见的指纹）、只给 AI 用 | 按设计延后 | 阶段 2、阶段 3。 |
| 上报数据防篡改 | 不好实现 | 场景和顺利率由用户本机算出再上报，用户可以改程序。见 [质疑与回应 C1](../vision/10-challenges.md)。 |
| 每个场景各自的顺利率 | 不好实现 | 现在链上分别统计场景分布和结果分布，要按场景拆开顺利率，需要换一种统计方式，或者改合约。 |
| 趋势图按上报时间统计 | 不好实现 | 这条链不支持查询历史事件，所以按服务收到上报的时间分周，不是按调用发生的时间。页面上已注明。 |
| 市场只能按编号打开别人的 Skill | 排期 | 还没有搜索和列表。 |
| 用户新建的场景标签只记在本机 | 排期（P2） | 跨用户汇总、收进下一版词表，放到赛后。 |
| Codex 里的 Skill 调用识别不完整 | 已知缺陷（P2） | Claude Code 的调用识别是准确的；Codex 有漏记和重复记的情况。 |
| 打开 session 的瞬间可能漏掉一条实时更新 | 已知缺陷（P2） | 新消息会在下一次更新时出现。 |

## 四、这一轮要测的场景

先跑场景 0，再按顺序测 1 到 4。场景 2 依赖场景 1，场景 3 依赖场景 2。每个场景都写了"应该看到"什么；和描述不一样、或者让你犹豫的地方，都值得反馈。

除了功能对不对，也请留意体验：文案是否看得懂、下一步该做什么是否清楚、等待是否太久、App 和网页看起来是否像完成的产品。

### 场景 0：准备两个身份

1. 按 [安装](README.md#安装每一轮通用) 跑完脚本。
2. 角色 A：
   ```bash
   source ~/.obelisk-hackathon/env.sh && obelisk --build
   ```
   然后 `cd ~/.obelisk-hackathon/workspace && claude`，对它说"帮我创建并激活 Obelisk 钱包"。
   - **应该看到**：先给出预览，你确认后才上链；激活交易能在 scan.bohr.life 上查到。
3. 在另一个终端里，用 `source ~/.obelisk-hackathon/env.sh b` 进入角色 B，同样建索引、创建并激活钱包。
4. 在浏览器里装好 MetaMask，准备两个账户：一个当接收者，一个当"拿到转发链接的人"。不需要任何 BOT。

### 场景 1：一句话沉淀 Skill（角色 A）

1. 在角色 A 的 Claude Code 里，说一件你真正做过、并且记得哪些对话相关的事，例如"把我最近写测试的做法沉淀成一个 Skill"。也可以直接用 `/obelisk-distill 把我最近……的做法沉淀成一个 Skill`。
2. **应该看到**：
   - 先单独列出找到的 session，每条带"命中：……"的理由，来源可能包括 Claude Code 和 Codex；
   - 最后一段简短报告：草稿名、证据数、踩过的坑和被纠正的条数、出生场景、指纹。
3. 试一次反例：说一件你没做过的事。**应该看到**：它说没找到直接证据，不会硬写。
4. 在角色 A 的终端里打开 App（`cd <仓库>/app && npm run dev`），进入左侧的 **Skill**。**应该看到**：
   - 草稿出现在"待确认的草稿"里；
   - 证据可以点开原 session，引文能定位到那条消息；
   - 出处卡里的坑和纠正标着证据编号；
   - 出生场景显示中文标签。
5. 点"继续修改"或"去掉"某条证据。**应该看到**：复制出一段 `/obelisk-distill …` 的 prompt，粘贴到 Claude Code 里能接着改。

### 场景 2：铸造并查看详情（角色 A）

1. 在 App 的草稿页点"确认并铸造"，把复制的 prompt 粘贴到 Claude Code。
2. **应该看到**：先给出铸造预览（作者、指纹、出生场景、费用由服务代付），你确认后才上链；返回的交易链接能在 scan.bohr.life 查到。
3. 回到 App，草稿变成"已铸造"。点"真实调用与族谱 →"进入详情页。**应该看到**：调用量为 0；场景和顺利率显示"尚未开启"，不是 0%；有版本表和族谱。
4. 记下 Skill 编号，比如 `#3`，场景 3 要用。

### 场景 3：别人取用、调用、上报（角色 B）

1. 在角色 B 的终端里打开 Claude Code，说 `/obelisk-skill-assets 取用 Skill #<编号>，装到当前项目`。
2. **应该看到**：先展示完整正文，并说明正文和链上指纹一致；你确认后才安装。
3. 新开一个 Claude Code session（`/clear` 或重新运行 `claude`），实际用两三次这个 Skill。
4. 说"开启 Obelisk 使用上报"。**应该看到**：先预览会上报什么、绝不会上报什么，并说明数据会以你的钱包地址公开在链上；确认后上报，交易可查。
5. 回到角色 A 的 App，打开这个 Skill 的详情页。**应该看到**：真实调用数等于角色 B 用的次数，钱包数为 1，本周趋势有数据。

### 场景 4：私密分享（角色 A 发给 MetaMask 账户）

1. 在角色 A 的 App 里打开一个不含敏感信息的 session，点页面顶部的"分享"。选消息范围，填 MetaMask 接收账户的完整地址。
2. 如果对方还没激活，对话框会给出一个激活链接。用装了 MetaMask 的浏览器打开它，签两次名完成激活，不需要付费。
3. 回到对话框，选次数（比如 2 次）和有效期，点"生成分享链接"，把复制的 prompt 粘贴到 Claude Code。
4. **应该看到**：
   - 隐私体检只列出检出项的类型和位置，不显示原值；
   - 你确认打码和规则后，它给出一个 `/s/…` 链接。
5. 用接收账户在浏览器里打开链接。**应该看到**：
   - 打开前说明要签两次名、都不花钱；
   - 打开后是对话时间线，打码处显示为"[已打码：…]"，整页铺着带你地址的水印；
   - 刷新页面不会多消耗一次打开次数。
6. 切换到 MetaMask 的另一个账户，再打开同一个链接。**应该看到**：拒绝页，说明这份分享属于谁。
7. 回到角色 A 的 App，进入 **Share**。**应该看到**：这条分享显示"已读"和时间，附链上回执链接。
8. 点"撤回"，把复制的 prompt 粘贴到 Claude Code 并确认。**应该看到**：
   - Share tab 显示"已撤回"；
   - 接收者再打开时看到"已撤回"的拒绝页，并说明加密副本已从服务删除。
9. 可选：用手机上 MetaMask 自带的浏览器打开一次分享链接，看手机上的排版。
