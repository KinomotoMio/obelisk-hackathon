# 为什么用 SQLite 而不是 MySQL

整理日期：2026-10-08。口述约一分钟，实际时长以练习为准。

## 一分钟回答

我参与的是校园活动报名网站，用 Node.js 和 SQLite，我负责报名接口、名额限制和邮件通知。当时实际采用了 SQLite，但现有记录没有说明选型理由，我也不能把它说成自己主导、比较过 MySQL 后的决定。

从我现在的理解看，SQLite 不用单独运行数据库服务，搭建环境比较简单，这是开发阶段可以考虑的优点。但这只是我现在对选型的理解，不能当成当时的理由。[技术依据](https://www.sqlite.org/serverless.html)

报名场景需要关注集中写入。SQLite 同一数据库文件同一时刻只能有一个写入者；如果以后需要大量并发写入或多台应用服务器共享数据，我会评估 MySQL 这类数据库。[技术依据](https://www.sqlite.org/whentouse.html)

目前项目还没正式上线，名额限制只测过普通报名，没有并发验证。所以我不能说 SQLite 已经满足高并发，也不能说换成 MySQL 就一定不会超额；还需要核对名额检查和写入的实现，再补测试。
